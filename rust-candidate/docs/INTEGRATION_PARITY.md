# DemoStrike Rust candidate: integration and parity contract

This document covers the seams between the [CS Demo Manager v3.20.1 source at `7270bc95c8cab87b7f9ddd490fea13c6eda3ace7`](https://github.com/akiver/cs-demo-manager/tree/7270bc95c8cab87b7f9ddd490fea13c6eda3ace7), the current DemoStrike, CsThrowBack, and ClipStrike/FilmCraft. It is a feature and acceptance ledger, not a claim that the candidate has implemented the upstream app. The upstream repository is MIT licensed; retain its notices for adapted code and check each reused asset and dependency separately. Do not incorporate DemoDesk AGPL code without a separate license decision.

## Architecture boundary

Preserve CS Demo Manager's React/TypeScript interaction patterns where licensed and suitable. Replace Electron main/preload, Node IPC and WebSocket orchestration at the **edge** with a typed Tauri command/event adapter backed by Rust, rather than keeping a second egui application shell. Keep upstream feature behavior visible as explicit gaps until each Rust command, UI state, and test is implemented. The first match slice is **read-only** against an isolated SQLite import; it must never mutate the original `.dem`, the prior DemoStrike DB, the CS Demo Manager PostgreSQL data directory, or existing `.cstrike`/`.fcproj` projects.

The upstream architecture includes a separate Go analyzer, PostgreSQL data service, Steam Game Coordinator helper, and CS2/CSGO server plugins. They are distinct components, not files automatically ported by translating the React UI. Preserve their protocols and data contracts in the source-file migration ledger; defer game integration and migration of existing PostgreSQL data until there is a tested adapter with rollback. No executable installation or local recording/render is part of this slice.

Do **not** copy upstream launcher side effects as-is. At this pin, [`start-counter-strike.ts`](https://github.com/akiver/cs-demo-manager/blob/7270bc95c8cab87b7f9ddd490fea13c6eda3ace7/src/node/counter-strike/launcher/start-counter-strike.ts) calls `killCounterStrikeProcesses()`, installs a server plugin, and may write `gamemode_custom_server.cfg`; [`watch-demo.ts`](https://github.com/akiver/cs-demo-manager/blob/7270bc95c8cab87b7f9ddd490fea13c6eda3ace7/src/node/counter-strike/launcher/watch-demo.ts) calls [`delete-json-actions-file.ts`](https://github.com/akiver/cs-demo-manager/blob/7270bc95c8cab87b7f9ddd490fea13c6eda3ace7/src/node/counter-strike/json-actions-file/delete-json-actions-file.ts), which removes the demo-adjacent `.json` file. Those operations conflict with preserving an existing game process, configuration and project data unless a later adapter proves ownership, backups and exact restoration. The candidate's read-only slices must not invoke them.

Define a shared immutable selection as `(demo_sha256, match identity, round number, event identity, throw tick, player SteamID64, map)`. A database row ID is local to a database, so it cannot be the sole project or capture identity. The authoritative clock for all demo-derived views is **integer demo tick** plus the source tick rate. Convert to seconds or frames only at display/export boundaries and specify rounding. Selection changes should update event table, radar trajectory, round timeline, inspector and any editable sequence without silently launching the game. Absent positions, unsupported maps, and missing radar art need honest empty states.

For native capture, continue current DemoStrike's `CaptureRequest` versioned, SHA-bound contract and three planned roles (`player_pov`, `projectile`, `third_person_reference`). `observer_slot_candidate` is a hypothesis until checked against actual game identity. HLAE/raw-take review, listened audio, proof frames, receipt sealing, muxed stream probe and editable project import are separate gates. Do not mark a take accepted when a source monitor merely opens it.

## Slice gates

1. **Read-only match slice:** Current source exposes typed `list_matches` and `get_match_detail` commands from an isolated SQLite DB; the latter includes overview, players, rounds, and utility rows. React library/overview is implemented in source but still needs a native build and populated GUI capture. A read-only Python check compares database values and the six Rust SQL queries; Rust tests are authored but unrun. Missing, malformed and empty DB cases are authored as Rust tests, not yet executed. The source `.dem` is not reparsed by this gate.
2. **Native import slice:** run candidate Rust parser on a copied or read-only real Cache demo and a corrupt fixture; compare exact source hash, entities and event totals to the older CLI baseline, then explain any intentional schema differences. Duplicate/cancel/atomicity tests pass before claiming import parity.
3. **Synchronized analysis slice:** one stable selection and integer tick connect finder/table, radar, round and inspector. Real data and adverse cases above pass; a current build supplies genuine populated screenshots.
4. **Editable project slice:** sealed fixture to FilmCraft handoff; saved project reopens, retains provenance and edits, refuses overwrite and unsupported legacy semantics. Keep editor backend behind a typed Tauri command or distinct launch boundary; do not embed the old egui shell inside React by assumption.
5. **Capture/runtime slice:** only after source, version, process ownership, audio/visual QC, crash recovery and disk-reserve gates are separately proven. No recording or render is required for the earlier slices.

Any GUI screenshot must identify exact build commit, fixture/DB identity and capture method. A source-level test, headless build, older CLI import or empty-window image is not populated GUI acceptance.

## Complete upstream regression checklist

This checklist is unimplemented in the candidate unless a row above supplies specific evidence. Do not treat a source adaptation, fixture, mock, or screenshot as equivalent to a packaged-app test.

- **Packaged bridge:** enumerate every `window.csdm` method, event, value and error from `src/preload/preload.ts` and `types/window-preload.d.ts`. Preserve dialogs, paths, persisted settings and table state, images, clipboard, window/tray/updater, audio, and exports. Validate WebSocket UUID-correlated success, reply error, server push, progress, disconnect, queue/reconnect and cancellation semantics. `getDemoAudioData` returns an `HTMLAudioElement` plus bytes; construct the DOM object in the webview rather than serializing it through Rust IPC. Replace Electron's Node daemon launcher when removing Electron.
- **Import matrix:** ZIP/GZ/BZ2/ZST, sibling `.dem.info`, checksums and duplicate identity, corrupt/truncated files, cancellation and partial analysis. Failed imports must never appear as complete matches or leave destructive changes.
- **Match statistics:** inventory overview, rounds, players, heatmap, weapons, duels, grenades, economy, 2D, video and chat. Golden demos must compare scoreboard, ADR/KAST, trade/opening kills, utility, economics, overtime and side changes against a pinned upstream baseline. One unknown winner in the Cache fixture stays unknown.
- **2D and audio:** exact integer tick seek, grenade states, radar/map transforms, Nuke upper/lower floor, voice and audio offsets. Reject unsupported maps and missing positions without inventing coordinates.
- **Capture:** verify chronological recording by start tick, final output ordering by sequence number, actual decoded frames, audible audio and duration, cancellation at every stage, and plugin/process cleanup. Upstream queue pause waits for the current video to finish; it is not a frame pause or crash resume. A packaged real-game run is required for acceptance.
- **Data and exports:** settings migrations and backups; JSON, XLSX, chat, voice, image and CLI exports; source-preserving rollback on failure. FACEIT in-app download is unavailable upstream after a private API change, so a browser fallback is the reference behavior.
- **DailyCSNades project:** stable grenade throw identity, same tick anchors and shared pause/resume for both cameras, reopening and editing a generated project, disk reserve on both raw and output volumes, and persisted job checkpoints that cannot duplicate clips.
