# DemoStrike capture request and reviewed receipt

A capture request freezes one selected imported event, the source-demo identity, event context, and three camera roles: player POV, projectile and third-person reference. Local preflight checks configured executables, hashes, disk headroom and conflicting processes without recording. A supervised offline pilot uses a bounded owned Windows Job Object; cancellation and timeout close the owned process tree.

Each recorded role needs its own video/audio media and runtime identity evidence. The technical QC worker validates streams, decodes, budgets and source identities. A human reviewer must separately preview each role, listen to game audio, select proof frames and record image/motion decisions. Receipt authoring rechecks those bytes. Sealing validates the request, receipt, source media and package binding without overwriting an existing destination. The portable sidecar stores hash-checked request and receipt bytes; raw WAV, console logs and proof PNG remain external audit evidence.

The source includes automated synthetic checks of request/receipt safety and a generated three-take QC/mux exercise. A fresh real capture and native-window review have not been verified. Do not infer human approval from a successful stream probe.
