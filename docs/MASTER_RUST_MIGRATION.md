# DemoStrike — ordered execution task list

**Snapshot: 28 October 2026.** This is an execution queue, not a completion or delivery-date promise. The historical repository plan is [`rust-candidate/docs/PLAN.md`](https://github.com/Gerbzz/DemoStrike/blob/69a0bfc6dc885cee0cd02514003a3d8c9ee7066c/rust-candidate/docs/PLAN.md); its detailed [integration and acceptance ledger](https://github.com/Gerbzz/DemoStrike/blob/69a0bfc6dc885cee0cd02514003a3d8c9ee7066c/rust-candidate/docs/INTEGRATION_PARITY.md) and [file migration ledger](https://github.com/Gerbzz/DemoStrike/blob/69a0bfc6dc885cee0cd02514003a3d8c9ee7066c/rust-candidate/docs/MIGRATION_LEDGER.csv) are the supporting maps. That historical file is not this master list. This document is proposed as `docs/MASTER_RUST_MIGRATION.md`; the historical plan and parity documents remain unchanged.

**Final direction: migrate the complete application, including UI rendering, controls and state, into Rust** while faithfully preserving the original CS Demo Manager UI, layout and interaction behavior. Replace Electron/Node/services with actual Rust implementations. React/TypeScript is a temporary source reference and transitional integration only—not the final runtime or evidence of a completed Rust port. The implementation technology must faithfully reproduce the original UI; a redesigned egui shell is not accepted. Preserve CsThrowBack workflows and editable FilmCraft projects. Source is [DemoStrike main at `69a0bfc`](https://github.com/Gerbzz/DemoStrike/tree/69a0bfc6dc885cee0cd02514003a3d8c9ee7066c) and [CS Demo Manager v3.20.1 at `7270bc95`](https://github.com/akiver/cs-demo-manager/tree/7270bc95c8cab87b7f9ddd490fea13c6eda3ace7); the [baseline and boundary](https://github.com/Gerbzz/DemoStrike/blob/69a0bfc6dc885cee0cd02514003a3d8c9ee7066c/rust-candidate/docs/UPSTREAM_BASELINE.md) distinguish staged upstream source from working ports. TypeScript repairs may be necessary to retain the UI, but **are not Rust migration**. The rejected [egui PR #17](https://github.com/Gerbzz/DemoStrike/pull/17) is not the path to merge.

## How to run the queue

Each numbered package is a reviewable slice, not a claim of existing functionality. A role is a responsibility, not a claim that someone is currently assigned. At each confirmed checkpoint at **midnight, 3 AM, 6 AM, 9 AM, noon, 3 PM and 6 PM America/New_York**, the implementer records the exact revision, change, tests and blockers; an independent reviewer inspects behavior, tests and evidence; the coordinator marks **accepted**, **rework**, or **blocked** and selects the next eligible package. A reviewer must not approve their own work. Keep working on a dependency-independent eligible slice if another is blocked. Do not treat a checkpoint as acceptance, and do not promise a week-long completion date. An existing 8 PM evening task reconciles owners; these schedules are managed separately from this document, which does not itself schedule or run workers.

**State key:** IN REVIEW = change/test evidence exists but review and broader checks are outstanding; PLANNED = not asserted complete; BLOCKED = cannot advance until its named gate clears. Every accepted slice updates the migration ledger and includes a source-matched test or native evidence as relevant.

## Guardrails and open holds

- Preserve original demos, user databases, existing projects, and pre-existing game sessions. Never copy destructive upstream launcher actions blindly. No executable downloads, plugin installation, game launch, recording, rendering, or migration of real user data is authorized merely by this list.
- The **`lib.rs`, CSP and publisher holds remain in force**; this draft does not resolve or authorize changes to those held areas. Escalate the exact proposed change for the required review/authorization rather than bypassing a hold.
- [Integration acceptance](https://github.com/Gerbzz/DemoStrike/blob/69a0bfc6dc885cee0cd02514003a3d8c9ee7066c/rust-candidate/docs/INTEGRATION_PARITY.md) distinguishes candidate gaps from existing DemoStrike/CsThrowBack source seams. Respect upstream notices and review separate assets/dependencies and HLAE licensing. No private demo, media, credentials, machine-specific paths, or unpublished CsThrowBack checkout belongs in the public repo.
- **Immediately next:** independent review and broader verification of DS-01, including its worker-claim race fix; then DS-02 unless its dependency is blocked. If blocked, DS-03 contract inventory can progress without changing the held queue file.

## Master scope inventory and assignment plan

**Audit status:** The pinned ledger inventories **3,168 tracked non-directory upstream entries** and provides categories, targets and status per entry. At this checkpoint it classifies 2,822 as `source_staged_unported`, 304 as `unported`, 40 as `not_applicable` and two as `adapted_partial`. These are **ledger classifications, not a fresh function-by-function audit**, and must be reconciled against newer candidate changes before dispatch. The staged-source check covers 2,827 paths; it is not a feature-parity check. Inventory counts do not establish that every external dependency, runtime behavior, permission, asset, or source path has been audited. [Baseline](https://github.com/Gerbzz/DemoStrike/blob/69a0bfc6dc885cee0cd02514003a3d8c9ee7066c/rust-candidate/docs/UPSTREAM_BASELINE.md) and [inventory](https://github.com/Gerbzz/DemoStrike/blob/69a0bfc6dc885cee0cd02514003a3d8c9ee7066c/rust-candidate/docs/UPSTREAM_INVENTORY.md) contain historical snapshots: reconcile their stale candidate-status and design statements with current code and the explicit original-UI direction before updating status. In particular, old adapted-screen/egui wording does not authorize a redesign. The list below covers **identified responsibility areas**, not a verified exhaustive functional census.

**Dispatch rule:** One implementer per bounded subtask, a different reviewer per completed change, and a coordinator to resolve dependencies/ownership conflicts. These are assignment *plans*, not claims that additional subagents are already working. The active DS-01 race fix finishes independently; do **not** start broad parallel assignments until this master list has been reviewed, reconciled and split into concrete non-overlapping slices. Once approved, dispatch only eligible tasks with acceptance criteria, isolated branches and review evidence. For each item below, extract exact calls/controls into the ledger, label implemented/partial/unported/unknown with revision-linked evidence, and add missing work instead of assuming a file count means behavioral coverage.
